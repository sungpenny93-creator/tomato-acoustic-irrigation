# 🍓 樹莓派快速部署手冊

> 給「番茄生理聲學監測與自動化灌溉系統」用的操作速查表。
> 每次要用樹莓派時翻這份就好，不用重看整份 README。

**基本資料（依你的實際狀況修改）**

| 項目 | 值 |
|------|-----|
| 使用者名稱 | `penny` |
| 主機名稱 | `raspberrypi.local`（或直接用 IP） |
| IP（會變動） | `192.168.0.6` |
| 專案路徑 | `~/tomato-acoustic-irrigation` |
| 網頁埠號 | `5000` |

---

## 0. 先搞懂系統在做什麼

啟動 `pi.web_controller`（或 `pi.monitor`）之後，同時有兩個東西在背景跑：

| 功能 | 何時跑 | 存不存檔 | 需要模型嗎 |
|------|--------|----------|-----------|
| **① 即時訊號**（波形＋頻譜圖） | 一啟動就**自動**跑，每 2 秒一次 | ❌ 不存（暫存檔覆蓋） | 不需要 |
| **② AI 自動監測** | 要在網頁點「啟動監測」才跑，每 300 秒一次 | ✅ 存到 `unlabeled/` | 需要（但目前判斷無意義） |

另外有一個**不會自動跑**、要手動下指令的工具：

| 功能 | 怎麼用 |
|------|--------|
| **③ 色塊分布比對** | `python -m pi.similarity_classifier ...`，需要先有標記好的範本資料 |

**目前流程的斷點**：② 存下來的錄音全部在 `unlabeled/`（沒標籤），
③ 需要標好 `normal/` 和 `thirsty/` 的資料才能建範本。
中間缺「怎麼知道番茄現在渴不渴」這一步（土壤濕度感測器，或人工判斷後手動分類）。

## 1. 插電後，我要 SSH 進去測試 / 下載東西

### 1-1. 開機

1. 接上電源（SpikerBox 的 USB 線也先插好）
2. 等 **40～60 秒**讓它開機完成

### 1-2. 從電腦 SSH 連進去

在電腦開終端機（PowerShell 或 Git Bash）：

```bash
ssh penny@raspberrypi.local
```

連不上就改用 IP：

```bash
ssh penny@192.168.0.6
```

> 兩個都連不上 → 樹莓派可能還沒開完機，或拿到不同 IP。
> 去路由器後台查目前 IP，或接螢幕看一次。

### 1-3. ⚠️ 先停掉開機自動啟動的服務

**這步很重要。** 如果你已經裝了 systemd 服務（見第 2 節），
它正佔用著 SpikerBox 的序列埠。不先停掉就手動跑程式，
兩邊會搶序列埠，撞出 `(5, 'Input/output error')`。

```bash
sudo systemctl stop tomato.service
```

> 還沒裝服務的話，這行會說找不到，可以略過。

### 1-4. 進專案、更新程式碼、開虛擬環境

```bash
cd ~/tomato-acoustic-irrigation
git pull
source venv/bin/activate
```

> `git pull` 說 `not a git repository` 或 `no tracking information` →
> 見第 3 節「Git 相關」。

### 1-5. 確認 SpikerBox 有被認到

```bash
ls /dev/ttyACM*
```

| 結果 | 意思 | 怎麼辦 |
|------|------|--------|
| 出現 `/dev/ttyACM0` | ✅ 正常 | 繼續下一步 |
| `No such file or directory` | 裝置沒被認到 | 拔掉 SpikerBox USB → 等 10 秒 → 插回 → 再打一次 |

### 1-6. 手動啟動（測試用）

```bash
python -m pi.web_controller
```

看到這行就代表 SpikerBox 連上了：

```
★ 成功連接 Plant SpikerBox: /dev/ttyACM0
```

然後手機／電腦瀏覽器打開：

```
http://raspberrypi.local:5000
```

> 第一次開、或剛更新過程式 → 一定要**強制重新整理**（`Ctrl + Shift + R`），
> 不然瀏覽器會用快取的舊版 JS／CSS，畫面不會更新。

停止：按 `Ctrl + C`。

### 1-7. 測試完，恢復自動運作

```bash
sudo systemctl start tomato.service
```

## 2. 讓樹莓派插電後自己開啟功能

用 **systemd 服務**，設定一次就好，之後插電開機自動跑，
不用接螢幕鍵盤、不用 SSH、不用打指令。

### 2-1. 安裝（只要做一次）

```bash
cd ~/tomato-acoustic-irrigation
git pull

sudo cp deploy/tomato.service /etc/systemd/system/tomato.service
sudo systemctl daemon-reload
sudo systemctl enable tomato.service    # 設定成開機自動啟動
sudo systemctl start tomato.service     # 現在就先啟動一次
```

> 如果你的使用者名稱不是 `penny`、或專案不在 `/home/penny/tomato-acoustic-irrigation`，
> 先 `nano deploy/tomato.service` 把 `User=` 和路徑改掉再 `cp`。

### 2-2. 確認有沒有成功

```bash
sudo systemctl status tomato.service
```

看到綠色的 **`active (running)`** 就成功了。按 `q` 離開。

### 2-3. 之後怎麼用

插電 → 等 30～60 秒 → 手機打開 `http://raspberrypi.local:5000`，就這樣。

### 2-4. 服務常用指令

| 指令 | 作用 |
|------|------|
| `sudo systemctl status tomato.service` | 看現在是不是在跑 |
| `sudo journalctl -u tomato.service -f` | 即時看 log（`Ctrl+C` 離開） |
| `sudo systemctl stop tomato.service` | 停掉（要手動除錯前必做） |
| `sudo systemctl start tomato.service` | 啟動 |
| `sudo systemctl restart tomato.service` | 重啟（更新程式碼後用） |
| `sudo systemctl disable tomato.service` | 取消開機自動啟動 |

### 2-5. 更新程式碼後要重啟服務

`git pull` 之後服務不會自動套用新程式，要手動重啟：

```bash
cd ~/tomato-acoustic-irrigation
git pull
sudo systemctl restart tomato.service
```

## 3. 常見問題排除

### 序列埠 / SpikerBox 相關

| 症狀 | 原因 | 解法 |
|------|------|------|
| `(5, 'Input/output error')` | 序列埠被別的程式佔住 | `sudo systemctl stop tomato.service`，再 `pkill -f "pi.web_controller"; pkill -f "pi.monitor"`，還不行就拔插 USB |
| `ls /dev/ttyACM*` 找不到裝置 | USB 掉線 | 拔掉 SpikerBox USB → 等 10 秒 → 插回。還是不行就重開機 |
| 網頁顯示 `mock`／log 一直印「產生靜音測試」 | 沒抓到硬體，跑在模擬模式 | 回去做 `ls /dev/ttyACM*` 確認裝置在不在 |
| log 一直印 `序列埠讀取超時` | `config.json` 的 `sample_rate` 設錯 | 序列埠 Plant SpikerBox 要設 `10000` |

### 網頁相關

| 症狀 | 解法 |
|------|------|
| `raspberrypi.local` 打不開 | 改用 IP；或樹莓派上 `sudo apt install -y avahi-daemon` 後重開機 |
| 畫面沒更新／新功能沒出現 | 瀏覽器**強制重新整理** `Ctrl + Shift + R` |
| 完全連不上 | 確認手機和樹莓派在**同一個 Wi-Fi**；`sudo systemctl status tomato.service` 看服務有沒有在跑 |

### Git 相關

| 症狀 | 解法 |
|------|------|
| `not a git repository` | 資料夾是複製來的不是 clone 的。見下方「重新接上 git」 |
| `no tracking information for the current branch` | 分支沒追蹤遠端。見下方「重新接上 git」 |
| `Your local changes would be overwritten` | 樹莓派上改過檔案。`git stash` 再 `git pull` |

**重新接上 git（會用 GitHub 版覆蓋本機修改，`venv/`、`models/`、`data/` 不受影響）**

```bash
cd ~/tomato-acoustic-irrigation
git stash
git fetch origin
git checkout -B main origin/main
git pull
```

### 訊號品質判讀

看網頁「即時訊號」卡片下面那行數字：

```
SR=10000HZ  SAMPLES=20000  RMS=0.0113  PEAK=60HZ  CLIP=0.0%
```

| 情況 | 代表 | 怎麼調 |
|------|------|--------|
| `CLIP` 超過 0%、`RMS` 接近 1 | 訊號爆表、被削平 | 電極沒夾好在亂跳，或增益太大 |
| `RMS` 小於 0.005 | 訊號太弱 | 電極接觸不良 |
| `PEAK=60HZ` 且很明顯 | 市電雜訊主導 | 黑夾子確實壓進濕土裡接地 |
| **理想狀態** | `CLIP=0%`、`RMS` 約 `0.01～0.3` | ✅ |

## 4. 常用指令速查

```bash
# ── 連線 ──────────────────────────────
ssh penny@raspberrypi.local

# ── 每次手動測試的標準流程 ──────────────
sudo systemctl stop tomato.service        # 1. 先停服務
cd ~/tomato-acoustic-irrigation           # 2. 進專案
git pull                                  # 3. 更新
source venv/bin/activate                  # 4. 開 venv
ls /dev/ttyACM*                           # 5. 確認裝置
python -m pi.web_controller               # 6. 啟動
#    ... 測試完按 Ctrl+C ...
sudo systemctl start tomato.service       # 7. 恢復服務

# ── 診斷工具 ──────────────────────────
python -m pi.test_spikerbox               # SpikerBox 硬體診斷
python -m pi.spectro_web                  # 只看即時頻譜（獨立頁面）
python -m pi.sensors                      # 測溫度＋土壤濕度感測器

# ── 色塊分布比對 ──────────────────────
python -m pi.similarity_classifier check          # 盤點已標記資料
python -m pi.similarity_classifier build          # 建立範本
python -m pi.similarity_classifier test 某檔.wav  # 測單一檔案

# ── 資料相關 ──────────────────────────
ls data/spikerbox_raw/                    # 看錄了哪些日期
du -sh data/spikerbox_raw/                # 看佔多少空間
```

## 5. 蒐集範本資料的流程（之後要做的）

1. **跟教授確認定義**：「狀況一」「狀況二」具體是什麼
   （例如：澆水後 1 天內 vs 停水 5 天且葉片明顯萎凋）
2. **錄音**：讓系統跑著，錄音會自動存到
   `data/spikerbox_raw/<日期>/unlabeled/`
3. **標記**：依照**獨立於 SpikerBox 的判斷依據**（土壤濕度感測器讀數、
   肉眼看葉片萎凋、停水天數），把音檔搬到：
   ```
   data/spikerbox_raw/<日期>/normal/     ← 正常
   data/spikerbox_raw/<日期>/thirsty/    ← 缺水
   ```
   > ⚠️ 不能用 SpikerBox 的聲音自己判斷自己，那是循環論證。
   > 中間「說不準」的過渡期資料**不要用**，只留兩端很確定的。
4. **每組至少 20 筆**之後，建立範本並測試：
   ```bash
   python -m pi.similarity_classifier build
   python -m pi.similarity_classifier test 某筆錄音.wav
   ```
